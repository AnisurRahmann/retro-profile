## What I built

- `pnpm lab:shots` — review shots of the lab: states A–C × tiers high/medium/low × 1440×900 DPR 2 and 375×812
  DPR 3 (mobile emulated), plus two frames of A 10 s apart (wind drift), into
  `.shots/volumetric-lab/run-<YYYYMMDD-HHMMSS>/`, with `sheet.png`, a contact sheet of the whole run.
- `pnpm lab:gpu` — GPU ms/frame per state × tier at 1920×1080 DPR 2 and 375×812 DPR 3 (from `GPU_TARGETS`),
  5 s per cell: prints a table (mean / p95 / max / samples / frames, the two §5 target cells marked `OVER`) and
  writes `<run>/gpu.json`.
- Both take the base URL from `LAB_URL` (default `http://localhost:$VOL_PORT`, else 3005), accept an optional
  state filter (`pnpm lab:gpu B`), and honour `RUN_DIR` (lab:gpu defaults to its own run dir; point it at a
  shots run to file the JSON next to those shots).
- BRIEF.md §11 "Tools" (appended); TASKS.md T6 section.

## Files (each owned file and what it holds)

- `scripts/probe/lab-shots.mts`: URL builder from `LAB_PRESETS` (+ `tier=`), readiness wait on `window.__vol`
  (`ready && frames > 40 && !error`, so a disposed StrictMode first instance never satisfies it), one page per
  cell, the drift pair on a live page, and the contact sheet (HTML grid, images inlined as data URLs,
  full-page screenshot — the `sheet.mts` technique, self-contained).
- `scripts/probe/lab-gpu.mts`: same URL/wait core; after a 1 s warmup, an in-page interval samples
  `window.__vol.gpuMs` every 100 ms for 5 s (deduplicated on `frames`, so one sample per rendered frame's latest
  finished query), then mean/p95/max. Launches Chromium with `--use-angle=metal --enable-gpu
  --ignore-gpu-blocklist` (see below).
- `package.json` (scripts block only): `lab:shots`, `lab:gpu`.

## Decisions (for M1/T8 to carry into docs/DECISIONS.md)

- Shots at DPR 2 (1440×900) and DPR 3 (375×812) to match the acceptance-measuring conditions and `GPU_TARGETS`,
  not DPR 1: reviewers judge what real hardware renders.
- GPU sampling reads the renderer's own per-frame `EXT_disjoint_timer_query_webgl2` result through
  `window.__vol` (the mechanism T0 built) rather than adding probe-owned queries; the probe owns no GL.
- Verified the GPU flags matter: with them the unmasked renderer is `ANGLE (Apple, ANGLE Metal Renderer: Apple
  M2)`; without them headless Chromium falls back to SwiftShader (T5 saw the same). The numbers below are real
  Metal, not software.
- Pre-T7 canonical numbers (real GPU): desktop 102–412 ms, mobile 33–142 ms — far over the §5 targets, as
  expected while the placeholder pipeline marches at full resolution every frame. Scaling is sane: high >
  medium > low, desktop > mobile, B/C (more coverage, fewer early exits) > A.

## Known issues

- **`gpuMs` can exceed `rafMs`** in heavy cells (e.g. A-high desktop 214 ms GPU at ~14 fps). The queries are
  T0's renderer mechanism (up to 4 pending, read back when available); with queued frames the reported value can
  be several frames old and include GPU work that overlapped the wall-clock window. Relative comparisons are
  trustworthy; T7 should re-check absolute semantics when it owns the frame loop.
- A first `lab:shots`/`lab:gpu` invocation against a cold dev server pays the Turbopack compile (the readiness
  wait allows 120 s per page).
- The very first gpu run (07:10, run-20261127-071002) measured the shared dev server mid-flux (the conductor was
  merging T1–T5 underneath); use run-20261127-072009 for anything citable.
- This worktree is shared by parallel sessions; the conductor fast-forwarded T1/T2/T4/T5 into `vol/T6-probes`
  while I worked. My commit stages only the T6 files.
