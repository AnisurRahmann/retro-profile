# T9 hand-off
Status: done. The review tooling is built, tested and run once end to end. The reference renders are not real yet:
`scale`, `reproject` and `accum` have no effect until T10 wires them, and the probe says so on every ref shot.

## What I built

1. **Four new `LabState` params**, parsed, serialised and clamped like the earlier ones: `scale` (0.25..1 or empty =
   the tier's), `reproject` (0 | 1, default 1), `accum` (integer 0..256, default 0) and `out` (`single` | `layered`).
   The camera azimuth is the existing `view` (there was nothing to add).
2. **Panel:** a "review" section with a cloud-scale slider (and "use tier scale"), a reprojection toggle, an accum
   frames field and an output select; the camera-view slider gained a typed "view azimuth" field. All native inputs,
   all named, all driven from the keyboard in a check (below).
3. **Probe states:** A-away (A with the camera 180° from the sun), A-ref and C-ref (`scale=1&reproject=0&accum=64`,
   1440×900 DPR 2 on the high tier only). A, B and C are untouched.
4. **100% crops** of every 1440×900 shot (six 600×600 in the 3×2 grid, and the 300 device px above the horizon),
   `crops.png` (one row per shot) and `pair-A.png` (each crop of A-high beside the same crop of A-ref).
5. **`metrics.json`:** `lattice`, `edgeWidth`, `bodyStd` per crop and `streak` on the band, plus a per-shot summary.
6. **`LAB_URL` is required** by `lab:shots` and `lab:gpu`: exit 2 with a clear message, no default port.

## Decisions (for M2 to carry into docs/DECISIONS.md)

- **D1: `LAB_URL` is required, with no default port.** Every session runs its own server on its own port, so a
  probe is told which one to shoot and never falls back to a port that may be another session's. `VOL_PORT` no longer
  stands in.
- **D2: the lattice resample is phase-locked to the cloud target.** The 2×2 checkerboard lives on the target's texel
  grid (texel k covers device px [k/scale, (k+1)/scale)). A box resample from a crop's own corner can land half a
  texel out of phase and average the checkerboard away. So `resampleRgb` takes the crop's origin in the frame and
  keeps only whole texels. A unit test shows the same pixels reading 0.8 in phase and 0.004 out of phase.
- **D3: the metric definitions.** Rec.709 luma of the sRGB bytes; HSV saturation. `lattice` counts a 2×2 window only
  when all four texels have saturation < 0.35, so cloud edges against sky don't inflate it. `edgeWidth` profiles the
  strongest 1% of Sobel edges ±12 device px with bicubic samples every 0.5 px. `bodyStd` uses whole 41×41 boxes from
  the crop's corner, mean saturation < 0.2.
- **D4: no image dependency.** PNG decode and encode are about 150 lines in `lab-image.mts`, verified byte-exact
  against Chromium. `sharp` is in the store only as a transitive dependency of `next`: importing it from the repo
  root fails (`ERR_MODULE_NOT_FOUND`, checked), so it would be a new dependency.
- **D5: the review params are optional on `LabState` for now.** `LAB_DEFAULTS` is declared `: LabState` and is not
  T9's to edit; `parseLabState` and `presetState` always set the four fields (`LabStateResolved`).
- **D6: probe modules import each other as `./x.mjs`.** Three tools have to agree: tsx does not resolve an
  extensionless import to a `.mts` file, `tsc` rejects an explicit `.mts` path without `allowImportingTsExtensions`,
  and all three accept `.mjs`, which TypeScript maps to `.mts`. See Request 3.
- **D7: one control beyond the four named in the task.** The panel has an accum frames field too, so a reference
  render can be set up by hand. It is one `NumField`; delete it if it is not wanted.
- **D8: `edgeWidth` is bounded by its window, and says so.** On known edges it reads within 1% from about 4 to 10
  device px. A wider edge no longer reaches both plateaus at ±12 px and reads narrow (−4% at 12.8 px, −7% at 15.4 px).
  The tests pin that.
