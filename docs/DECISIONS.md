# Decisions

Format: decision · rejected alternative · why.

## Foundation

1. **Rebuild in place on branch `redesign/talk-to-my-agent`, off `main`.** · Branching off `redesign/garage-gym`. · The brief replaces the Garage Gym direction; `main` holds the source-of-truth gym data (`src/data/gym.ts`). The CRA files were removed on this branch only.
2. **Gym data ported into `content.lifts`.** `src/data/gym.ts` (main @ 9fb4a5a): seven days in training-week order (Friday first), headline + emphasis merged into `title` ("Squat (Heavy)"), notes kept, Thursday's program rules moved to `lifts.rules`. Photos and the phone-frame UI were dropped (plain tables per the brief). `/gym` 301s to `/lifts`.
3. **TypeScript 5.9, not 7.0.** · TS 7 (native port) is latest. · Next 16's type plugin and typescript-eslint target 5.x; 7.0 is weeks old.
4. **Dev dependencies beyond the allowed list** (all build/test tooling, none ship to the browser): `typescript`, `@types/*`, `eslint` + `eslint-config-next`, `prettier`, `@tailwindcss/postcss` (required by Tailwind 4), `tsx` (runs `scripts/*.ts` and evals), `yaml` (parses `evals/cases.yaml`; a hand-rolled YAML parser would be a bug farm).
5. **Placeholders resolved in one place (`src/site.ts`).** · Checking `[[` in each component. · One rule set (optional → dropped, required → item hidden, human receipt → excluded) and one test over everything components can see.
6. **Copy includes UI strings.** Nav labels, headings, button labels, chat errors and privacy text live in `content.ui`, so "components never hardcode copy" holds literally and the copy-scan test can be strict.
7. **Portrait fallback.** `public/shakil.jpg` is missing; `Portrait` checks the file at build time and renders an "as" monogram circle instead. No code change needed when the photo lands.
8. **Callback AI URL filled from Shakil's own project notes** (`brain/projects/callback-ai.md`, deployed 2026-09-23) rather than left as a placeholder. Flagged in OPEN_QUESTIONS #4.

## Design

9. **Tile colours** chosen as dark muted mid-tones (luminance below `--graphite`, ≥ 4.5:1 against the `--text` monogram); a vitest computes the ratios from the CSS.
10. **Status line height reserved per breakpoint** (2 lines under 640px, 1 above) so the longest line wrapping never shifts the one-liner. Typed-in remainder is rendered `invisible` so wrapping is final from the first character.
11. **Show-more uses `inert` on the collapsed panel** in addition to `aria-expanded`, so hidden cards can't be tabbed to.
12. **Show-more panel class is `.reveal`, not `.collapse`.** Tailwind 4 ships a `collapse` utility (`visibility: collapse`) that silently overrode the panel. Caught by e2e.

## Agent

13. **No vector search.** · RAG over the content. · The whole knowledge base is ~2.3k tokens (test fails over 15k). It fits in a prompt-cached system prompt; retrieval would only add misses and latency.
14. **Model: `claude-haiku-5-5`** (current Haiku per the Claude API skill's model table, cached 2026-11-03), overridable with `CHAT_MODEL`. Never routed to a top-tier model.
15. **No `temperature`.** · The brief's 0.3. · Haiku 5.5 rejects non-default sampling values with a 400, and API version 2026-10-21 rejects them on every model. Determinism comes from the rules and grounding instead.
16. **`output_config.effort: "low"`, adaptive thinking left on (the model default).** · Disabling thinking. · Chat answers are short and latency-sensitive; low effort keeps thinking small. Disabled thinking has documented failure modes (tool calls written as text). `max_tokens` stays 700 as briefed; thinking tokens count against it, so watch `stop_reason: max_tokens` in live evals.
17. **Cache breakpoint on the single system block (rules + knowledge).** Tools render before system, so the breakpoint caches tools + system together across turns and visitors. The prompt has no per-request values. Haiku 5.5's minimum cacheable prefix is 512 tokens; ours is ~4k.
18. **Tool loop: call 1 with `tool_choice: auto` + `disable_parallel_tool_use`; call 2 only if a tool ran and the model hadn't written any text yet (or the tool errored), with `tool_choice: none`.** · Always making the second call. · Saves a round trip on most tool turns, and hard-guarantees ≤ 2 calls and ≤ 1 tool per turn. Forced `tool_choice` (`any`/`tool`) would 400 on current models anyway.
19. **Tools are not `strict`.** `book_call.reason` is optional, which strict mode doesn't allow; every input is zod-validated server-side instead, and a tool with a `max_tokens` or `refusal` stop never runs.
20. **No eager input streaming on tools.** Inputs are a few words; buffering them costs nothing.
21. **Rate limit + budget fail closed.** · Fail open on DB errors. · A broken limiter must not turn into an unbounded bill. In mock mode only, an in-memory limiter stands in so tests and e2e run without Supabase.
22. **Logging via `after()`** (Next's post-response hook) so it never delays or breaks the stream; errors are swallowed.
23. **Kill switch is build-time for the page, run-time for the API.** `/chat` must stay static, so it reads `CHAT_ENABLED` at build; `/api/chat` reads it per request and returns `disabled`. Flip the env var and redeploy to switch the page.
24. **`server-only` package added** so server modules (keys, Supabase) fail the build if imported into client code. Aliased to an empty module in vitest.
25. **Intro honeypot answers 200** so bots get no signal; rejected silently.
26. **Retention via pg_cron** (`purge_chat_logs()` daily at 03:17 UTC): messages and sessions after 90 days, rate windows after 2 days. Intros are kept (they are leads), as the privacy page says.
27. **`ProjectCard` is pure (labels passed in, no `site.ts` import)** so `/chat` reuses the exact home-page card without bundling the content file into client JS. The chat page passes `ui.chat` copy and the link allowlist as props.
28. **Chat history sent to the API is rebuilt from UI state:** failed turns are dropped with their question so roles always alternate; a tool-only reply is sent as `[showed book call]` so the model knows what it did.
29. **`?q=` is read on the client after hydration** (the page must stay static). It only prefills; it never sends.
30. **Focus ring on the chat textarea is the global amber `:focus-visible` ring** rather than a softer border change: accessibility wins over the calmer look (logged per the brief's rule).

## Evals

Unknowns must contain a don't-know phrase and no number that isn't in knowledge.md.

34. **`pnpm test` asserts structure, the grader itself (with synthetic answers) and the mock-scripted tool cases.** The mock can't answer facts, so its overall pass rate (~69%) is not a gate; `pnpm eval:mock` prints it for plumbing checks.

## Signal Field

39. **Final constants** (`SF` in `src/lib/signal-math.ts`; the GLSL is generated from the same object, so TS and shader can't drift):
    pitch 22 · rBase **0.9** (brief 0.8) · rGain 1.1 · aa 0.75 · aMin **0.16** (brief 0.10) · aMax 0.62 · idle 0.06, λ 900 px, period 9 s, noise 0.0015 / 0.05 / warp 1.7 · cursor gain **0.45** (brief 0.35), σ 140, smoothing τ 0.08 s, leave fade 0.4 s · ripples v 420 px/s, w 18 px, τ 1.6 s, 8 emitters, inactive after 5τ · column mask **0.25** (brief 0.35), ramp 80 px into each gutter, flat below 808 px · amber ≤ 35% where masked ripple > 0.5.
    - Column 0.35 → 0.25: the Playwright guard measured 4.13:1 for `--graphite` against the brightest dot pixel behind the hero paragraph at a ripple peak (needs 4.5). At 0.25 the column peak dot alpha is 0.155 and the guard passes. The brief's ≈0.25 estimate was for alpha; a dot-centre pixel at that alpha is too bright.
    - aMin 0.10 → 0.16 and rBase 0.8 → 0.9: at 1920 the gutters still read as empty. Column idle alpha stays ≤ 0.047 (guard ≤ 0.06).
    - Cursor 0.35 → 0.45: the glow didn't register in the gutter; over the column it's masked to 0.25 × and stays faint.
40. **The column mask scales the whole dot alpha, floor included** (`alpha = mix(aMin, aMax, I_raw) × mask`), so the column stays within mask × [aMin, aMax] as the readability guard requires. Radius and colour use the masked I.
41. **Ramp sits in the gutter** (smoothstep 0 → 80 px past the column edge), so text at the column edge never gets gutter-strength dots.
42. **Instanced dot quads instead of one full-screen triangle.** · The brief's full-screen fragment shader. · Measured on Chrome/ANGLE Metal, Apple M2, 3840×2160 (1920×1080 at DPR 2), 8 active emitters: full-screen shader 4.4–6.6 ms; with an early exit for fragments outside any dot 2.0 ms; an empty full-screen pass alone ~1.0–1.2 ms. Instancing evaluates the intensity once per dot in the vertex shader (~4.4k instances) and rasterizes only dot pixels: 1.13–1.25 ms total, of which ~1.05 ms is the clear/present floor of a 3840×2160 surface (clear-only frame measured at 1.03–1.09 ms). 0.57 ms at 1920×1080 DPR 1. Same intensity function, same per-cell-centre semantics, same pixels.
43. **Init split across tasks** (context, then shader compile polled through `KHR_parallel_shader_compile`, then wiring). The first version blocked the main thread on `LINK_STATUS` and added a ~99 ms long task under Lighthouse's 4× CPU throttle (TBT median 24 → 58 ms). After the split: median 24 ms, no Signal Field long task.
44. **Test-only hooks (`window.__signalFrames`, `window.__emitSignal`) exist only in a separate test build** (`NEXT_PUBLIC_E2E=1`, `distDir .next-e2e`, `pnpm e2e`), so production bundles never contain them and the e2e build never overwrites `.next`.
45. **Dots are anchored to the viewport** (fixed canvas), so content scrolls over a still grid: no parallax, nothing moves on scroll, and no emits on scroll.
46. **Reduced motion:** one static frame (idle at t = 0, no cursor, no ripples). No loop and no bus subscription, re-checked on the media-query change event.
47. **GPU timing is dev-only** (`EXT_disjoint_timer_query_webgl2`, `[signal-field]` console prefix). Headless Chrome's default SwiftShader doesn't expose the extension; measure with `--use-angle=metal --enable-gpu --ignore-gpu-blocklist` (`scripts/probe/gpu.mts`, needs `pnpm dev` on :3000).
48. **Stop e2e dispatches the click.** The docked composer moves while tokens stream, so Playwright's stability wait could outlast the stream (flaked once at 30 s).

## Chat availability (2026-11-25 review)

49. **One availability check, `getChatAvailability()` (`src/agent/availability.ts`), used by both `/chat` and `/api/chat`.** It zod-validates `ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RATE_SALT` (≥ 16 chars), optional `CHAT_MODEL`, and parses `CHAT_ENABLED` strictly (`true`/`false`, default `true`; anything else → `misconfigured`). `/api/chat` returns 503 `unavailable` only when this says not enabled. `CHAT_MOCK=1` (tests, e2e, screenshots) needs no external env.
50. **`/chat` is now rendered per request** (`force-dynamic`). · Keeping it static with a build-time read. · A static page reads env at build while the route reads it at runtime; that gap is exactly how the page showed a working input while every POST failed. Per-request rendering makes disagreement impossible. Lighthouse on `/chat` stays at 100 (see PROGRESS).
51. **Rate limiting fails OPEN on runtime Supabase RPC errors** (replaces #21's fail-closed). · Fail closed. · A transient DB blip shouldn't take the agent down for every visitor. The backstop is a per-instance token bucket (capacity 20/hour per IP hash for chat, 5 for intros, refilled linearly) plus a `[chat]` warning at most once a minute. A failed budget check also fails open, bounded by the same bucket. Risk accepted: during a long DB outage, global spend is bounded only per instance and per visitor. Missing configuration is not a runtime error: it never gets past the availability check.
52. **Anthropic API errors map to `upstream`, not `unavailable`,** so `unavailable` always means "switched off or not configured".
53. **Every error reply carries the book-a-call card.** `rate_limited`/`budget` → "That's a lot of questions…", `unavailable` → the kill-switch line, anything else → the generic line with the email.
54. **Amber focus rings only for keyboard focus, enforced with an input-modality attribute.** · Pure `:focus-visible` (+ `:has()` on the composer). · Browsers match `:focus-visible` on text fields even on a mouse click, which is what drew the amber box on click. A ~200-byte inline script in `<head>` sets `html[data-input]` to `pointer` on pointerdown and `keyboard` on Tab. Text fields lose the ring under `pointer`; the composer gets its amber ring on the box via `:has(textarea:focus-visible)` only under keyboard; mouse focus changes the border to `color-mix(graphite 45%, hairline)`. The attribute defaults to `keyboard`, so keyboard users without JS keep the ring. Buttons and links keep plain `:focus-visible` (browsers already skip it on click). Replaces #30.

## Signal Field tuning, review round 2 (2026-11-25)

55. **Constants, before → after:** aMin 0.16 → **0.16** (the review assumed 0.10; it was already raised in #39 and now reads clearly at 1440 and 1920, not busy, so no step-down) · rBase 0.9 → **1.0** · idle amplitude 0.06 → **0.09**. **Column mask stays 0.25, not 0.35:** at 0.35 the Playwright guard measured 4.13:1 for `--graphite` over the brightest dot pixel at a ripple peak (#39). At 0.25 with the new radius and idle values the guard still passes, and column idle alpha is ≤ (0.16 + 0.46 × 0.09) × 0.25 = 0.050 (≤ 0.06).
56. **Two emitter classes with per-emitter τ** (passed to the shader as `vec4 uE[N] = (x, y, amp, τ)`): ambient (status line, τ 0.9 s, amp 0.35) and interactive (pointer, click, chat send, stream chunks, tool cards; τ 1.6 s). **An emitter is active while A·e^(−Δt/τ) > 0.02**, replacing the fixed 5τ window. An ambient ripple goes quiet after 0.9 × ln(0.35 / 0.02) ≈ 2.58 s, inside the 3.2 s status cycle, so the home page drops to idle for ~0.6 s between lines.
57. **Render modes:** `full` (interactive ripple active, pointer moved < 2 s ago, or the cursor glow still fading) at the display rate (30 on coarse pointers) · `ambient` (only ambient ripples) at 30fps · `idle` at 15fps · `static` under reduced motion. Test builds expose `window.__signalMode`. Before this, the status line kept an emitter "active" (8 s window > 3.2 s cycle), so the home page never left full rate.
58. **Backing store = CSS size × min(DPR, 1.5)** (`SF.maxScale`). Measured at 1920×1080, DPR 2 (Chrome/ANGLE Metal, Apple M2, /lifts, 60 samples per run): scale 2.0 busy 0.75–0.89 ms, rest 0.90–1.10 ms · scale 1.5 busy 0.54–0.75, rest 0.53–0.61 · scale 1.0 busy 0.68–0.98, rest 0.34–0.40 (busy at 1.0 reads high because the GPU clocks down at light load). At 400% (`scripts/probe/crisp.mts`, cursor glow on the patch), 1.0 shows a visibly blurred halo; 1.5 is within a hair of 2.0. At rest, peak dot brightness is 27.0 / 23.0 / 22.1 (2.0 / 1.5 / 1.0). Not visible at 100% on a Retina display. 1.5 is the lowest scale without visible softening. Radii and the 0.75 px AA width are in CSS px (scaled by the backing scale in the shader), so dots keep their size at any scale. Dev and test builds accept `?sfscale=` for comparisons.
59. **Only active emitters reach the shader:** the CPU packs emitters whose A·e^(−Δt/τ) > 0.02 to the front and passes the count `uN`; the ripple loop breaks at `uN`. Idle frames run zero ripple iterations.
60. **Mid-stream list markers** (`- ` with no text yet) are skipped by the chat markdown parser, so a list doesn't flash an empty bullet while streaming (found in the 375px review shot).

## Sylhet Sky (replaces the Signal Field, 2026-11-25)

61. **New dependency: `suncalc` 1.9.0 (+ `@types/suncalc`).** Sun and moon position, moon illumination and sun times. ~2.5 kB gzip, MIT, no dependencies, stable for years. The only new dependency for the sky; it's excluded from the 9 kB sky budget by the brief. 1.9.0 rather than 2.x because the DefinitelyTyped types match 1.9.
62. **Weather comes only from `/api/sylhet`.** The browser never calls Open-Meteo, so no visitor IP reaches a third party. The route is `force-dynamic` (never prerendered, so `next build` never calls Open-Meteo); the upstream `fetch` uses `next: { revalidate: 900 }` and the response sends `public, s-maxage=900, stale-while-revalidate=3600`. That caps upstream traffic at ~96 calls a day. **Deviation:** a stale fallback response is cached for only `s-maxage=60` so the CDN doesn't pin a failure for 15 minutes.
63. **Open-Meteo licence and terms (read 2026-11-25).** Data are CC BY 4.0; attribution must be a link "next to any location Open-Meteo data are displayed", e.g. `<a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>`. It's in the label popover (next to the weather) and on /privacy. Free API = non-commercial only, < 10,000 calls/day (5,000/hour, 600/minute). The terms define non-commercial as "private or non-profit websites or apps that do not have subscriptions or advertising", but list "commercial products or promotional activities" as commercial. **Finding: this site has no ads or subscriptions, but it promotes Shakil's paid services, so it is a grey area, not clearly non-commercial.** Usage (~96 calls/day) is far under every limit. For certainty: ask Open-Meteo, or take their cheapest commercial API plan (OPEN_QUESTIONS #13). The terms also warn that shared-IP hosts (Vercel) can hit IP-based limits sooner; the 15-minute cache makes that unlikely.
64. **Normalised weather shape** adds `code` (the WMO code) to the briefed fields, so the label can say "light rain" (61/80) vs "rain" (63/81). WMO 66 (light freezing rain, not in the brief's table) → rain; anything unlisted → overcast. Numeric fields are nullable for the no-data fallback.
65. **`WEATHER_MOCK=1`** (e2e, screenshots) makes `/api/sylhet` return a recorded real response (`src/server/fixtures/open-meteo-sylhet.json`, Sylhet, 2026-11-25 08:15, fog, visibility 480 m) without network.
66. **Weather percentages on the gradient are relative** (OKLab L × (1 ± k)): "drop lightness 8%" = L × 0.92. Desaturation k = move k of the way toward the neutral grey of equal OKLab L (a, b × (1 − k)). Drizzle uses the rain modulation. "By day" scales with `dayness` = smoothstep(−6°, +8°).
67. **First-paint script uses a server-precomputed table, not inline OKLab.** · Inline keyframes + OKLab math. · (Superseded in part by #74: 4° steps, scrim added.) The table holds the full OKLab pipeline's output at 3° steps from −18° to +27° (16 × zenith, mid, dawn and dusk horizon); the script mixes neighbouring entries in sRGB, which at 3° apart is within ΔE_OK 0.03 of the real thing (tested). Script is ~1.06 kB with no suncalc; the NOAA estimate (3rd-order terms dropped) is within 0.41° of suncalc over 2026 at 30-minute steps (tested against the shipped string). It also sets `html[data-sky]` (state) before paint. Clear sky only; weather arrives with the controller and fades in over 4 s.
68. **suncalc's day cycle flips near solar midnight**, so morning/evening disagrees with the NOAA hour angle for ~10 minutes around midnight. Harmless: at night dawn and dusk horizons are the same colour. The test skips ±20 min around solar midnight.
69. **Sunrise/sunset vs Open-Meteo:** suncalc runs 1–2.5 min later than Open-Meteo across Aug–Dec 2026 and 21 June (worst raw delta 3.05 min, sunset 14 Sep). Open-Meteo prints whole minutes, so the test compares against the middle of that minute (worst 2.55 min, inside ±3).
70. **Palette retune for the contrast gate** (sweep in `tests/unit/sky-contrast.test.ts`): the brief's golden-hour horizons couldn't be made readable even at the 0.82 maximum scrim once +12% cloud tops or fog were added (worst 4.19:1 for `--graphite`, 8° fog dusk). Sunrise/sunset and golden horizons are now OKLab L × 0.90 with chroma × 1.12, so they stay amber rather than going brown: 0° dawn `#B9786A → #A96253`, dusk `#D9813A → #C86800`; +8° dawn `#C99A70 → #B68253`, dusk `#D99A55 → #C6812D`. Everything else is as briefed.
71. **The scrim is solved per height, not once.** · One `--scrim-a` for the whole column from the horizon worst case. · The sky is darkest at the zenith, so a single horizon-derived alpha made a dark lane from top to bottom. Five registered stops (`--scrim-0…4` at 0/25/50/75/100%) are each the maximum solve over their neighbourhood (sampled every 1/32 of the height), so linear interpolation never undershoots; the sweep checks 65 heights per case. `--scrim-a` remains (the maximum) for `window.__sky` and docs. The worst case still lands at the bottom at dusk, where the lane is visible; that's the cost of graphite text over an amber horizon and accessibility wins.
72. **Clouds and the horizon glow are drawn at 50% behind the column** (shader `col`, ramping out over 96 px, mirrored by `COLUMN_DAMP` in the solver), the same idea as the old field's column damping. The moon disc is drawn at 30% inside the column and stars at 50%; the solver includes the moon near its height. **Lightning is not in the guard**: it's a ≤ 260 ms double pulse on the cloud layer, not a state anyone reads against.
73. **Scrim edge fade is eased** (smoothstep-like stops over the briefed 96 px) because a linear alpha ramp shows Mach bands at both ends.
74. **First paint sets the scrim too**: three stops per table row (0, 50, 100%), one hex digit each, rounded up; the 25/75% stops take the max of their neighbours. Script: 1,483 B in production (< 1.5 kB); the `?sky=` parser adds ~120 B to dev and test builds only. The table step went from 3° to 4° (still within ΔE_OK 0.03 of the full pipeline, tested).
75. **Glass surfaces** (`.glass`): `--surface-glass` = `--surface` at 86% with `backdrop-filter: blur(10px) saturate(1.1)`, opaque `--surface` without backdrop-filter support. Used on project cards, the closer, receipts, tool cards, work-page chips, the chat composer and the user's bubbles. Card hover still goes to solid `--surface-2`.
76. **Label, popover and scrubber** (`SkyLabel`): one button (`aria-haspopup="dialog"`) under the one-liner; the popover is `role="dialog" aria-modal="true"`, traps Tab, closes on Escape, outside click or "Back to now", and returns focus to the button. The range input handles arrows (±5 min), PageUp/PageDown (±1 h), Home/End (00:00/23:55) itself, so behaviour doesn't depend on the browser's native page step. The way back to now is a 1.2 s ease-in-out on the preview minutes (instant under reduced motion). The popover is the tooltip: sun times, feels-like/humidity/wind, "Updated" + the Open-Meteo link next to the data. Sunrise/sunset come from Open-Meteo for today, from suncalc when there's no data or `?sky=` moves the date.
77. **Nothing time-dependent renders before hydration** (glyph, weather, preview): pages are static, so build time ≠ visit time. The server renders a 10 px placeholder and "--:-- in Sylhet"; weather text is appended on the same line, so CLS stays 0.
78. **Header dot kept** (CSS only, from `html[data-sky]`): amber at golden hour, graphite at 55% at night (nautical or darker), nothing otherwise. It's 6 px and reads as a status light, not fuss; drop the `.sky-dot` span if the review disagrees.
79. **Meteor after a reply only "at night"** = sun below −6° (past civil twilight), the same `isNightElevation` the agent tool uses.
80. **Sky JS (esbuild, minified, gzip, excluding suncalc and React):** lazily loaded renderer (WebGL + particles + loop) **8.8 kB** (budget 9 kB). The eager part (controller, scrim solver, label, clock, store) is 7.9 kB; unique total 13.4 kB. **The 9 kB budget holds for the renderer module, not for everything sky-related.** zod was kept out of the client (it briefly leaked in via the weather schema: +13 kB).
81. **`sylhet_now` is a data tool**: no card and no `tool` event on the wire; the turn always makes the second (text-only) call, even when the model wrote "Let me check." first (UI tools still skip it). It returns `{ time, weatherSummary, isNight }` from the same cached weather as `/api/sylhet` plus suncalc, so it costs no extra upstream call. A new `<local_time>` block in the system prompt (static text, so the prompt cache still holds) says: state the exact HH:mm factually, never speculate about sleep, schedule, whereabouts or reply speed.
82. **Evals:** new `availability` category (3 cases: is he awake, where is he right now, a personal-detail extraction attempt) with deterministic checks: `expect_tool: sylhet_now`, `expect_sylhet_time` (the reply contains the Asia/Dhaka HH:mm of the run, ±2 min) and a category-wide speculation blocklist (asleep, probably, at home, busy, …). The scripted mock passes all three. `eval:mock`/`eval:live` now run tsx with `--conditions=react-server` (the agent imports `server-only` modules); the mock run sets `WEATHER_MOCK=1`, as do vitest and the e2e servers, so no test touches Open-Meteo.
83. **Atmosphere GPU: texture value noise, 4 fbm octaves, backing scale 0.4 × DPR.** Measured with `scripts/probe/gpu-sky.mts` (Chrome/ANGLE Metal, Apple M2, 1920×1080 at DPR 2, `EXT_disjoint_timer_query_webgl2`, 6 × 60-frame averages):
    | shader | backing | state 5 (overcast, NE 15) | state 8 (thunder, bolt) |
    |---|---|---|---|
    | hashed value noise, 5 octaves (as built) | 0.5 → 1920×1080 | 4.1–5.7 ms | 3.8–4.3 ms |
    | hashed, 4 octaves | 0.5 | 4.8–5.7 ms (no gain, within noise) | 3.6–5.0 ms |
    | hashed, 4 octaves | 0.4 → 1536×864 | 2.5–3.3 ms | 2.5–2.8 ms |
    | **noise texture (256² R8, 1 filtered fetch per lookup), 5 octaves** | 0.5 | 2.3–3.2 ms | 2.3–2.7 ms |
    | noise texture, 4 octaves | 0.5 | 2.3–3.4 ms | 2.6–3.3 ms |
    | **noise texture, 4 octaves (shipped)** | **0.4** | **1.42–1.61 ms** | **1.42–1.72 ms** |
    The brief's ladder (octaves 5 → 4, then scale 0.4) alone wasn't enough; replacing the 4-hash value noise with a seeded noise texture (smoothstep-warped UVs, so it still interpolates like value noise) halved the cost. A clear night is ~2.1 ms at 0.5 because the cloud branch runs whenever cover > 0.5%; at 0.4 everything is under 2 ms. The look at 0.4 is unchanged in the review shots (the layer is all soft gradients).
84. **Client fetches `/api/sylhet` with `cache: "no-cache"`.** Found by the e2e poll test: the response's `stale-while-revalidate=3600` is meant for the CDN, but Chrome applies it too, so each 15-minute poll got the previous poll's copy from the HTTP cache and revalidated behind it (every update one poll late, plus an extra background request). `no-cache` makes the browser revalidate; the CDN still caches.

## Weather v6: clouds, rain, lightning, fog (2026-11-26)

Each entry is a place the work departs from the brief or from v5.1, with what was measured. Tasks W1–W7 in order; the evidence is in `.shots/v6/<task>/` and the log in docs/PROGRESS.md.

121. **Cloud sheets are read in log depth, not on the brief's flat plane.** The distance is as briefed (`planeZ = h / max(v, 0.02)`, heights 9 / 4 / 1.6, focal 0.9·W, haze over the last 4% above the horizon). The depth along the view is `s = h·k·ln(z / h)` with `k = cloudHz / (0.9·vw)` (`clouds.ts` `planePoint`). On a flat plane a cloud's height on screen falls as v² and its width only as v, so above about 20° every distant cloud is a line six times wider than it is tall: the first build drew lozenges and scratches. In log depth one pixel spans the same noise along both axes (unit test), so a cloud keeps its proportions at every distance.
122. **Worley is a texture, and the puff's normal comes with it.** F1 / F2 is a precomputed tiling 256² texture (`clouds.ts` `cellData`): one filtered fetch instead of nine hashes, on the GPU and in the CPU mirror. Its G and B hold the vector to the cell's centre, so F1 is its length and the puff's Lambert normal is its direction plus the first octave's slope (two more samples). The brief's normal from three density samples costs three times that, which the 2 ms budget doesn't pay for. MID is a low-frequency patch mask × the cell domes, not a literal 60/40 fbm blend: that read as specks at 1440×900. Octaves: LOW 4 (brief 5: the fifth is under 2 px everywhere but overhead), HIGH 3 (brief 4), SCUD 2. An octave whose wavelength is under about two pixels of the footprint is not sampled (`lod`).
123. **The clouds' horizon is the far hills' skyline**, not the viewport bottom: with the fixed band (from 1100px) the land covers the bottom of the viewport, so `cloudHz = vh − 0.66 × bandHeight`, and v runs 0…1 over the sky that is actually open. At the viewport bottom only v 0.82…1 was ever visible, which is no perspective at all. In scene mode it is the visible ground.
124. **Coverage is a quantile, and its soft edge is centred on it.** The density a coverage means is solved on the CPU from 1,024 samples of the sheet's own noise (`cloud-field.ts` `threshold`). Each sheet's edge (0.045 of density, a stratus deck 0.18, cirrus 0.25) starts half an edge under that density. Starting it at the density took 7 points off a 45% partly sky (measured 38%): the edge is half the noise's spread. `sky-clouds.test.ts` holds a 45% sky at 0.40–0.50 and a 98% deck above 0.95, averaged over where the wind has left the sheet.
125. **A stratus deck is thick everywhere.** Overcast and drizzle at LOW 0.98 are not a cumulus field with holes. Their thin patches keep 0.45 of the density and at least 0.86 opacity (`STRATUS`), so a thin patch is a little brighter (more light comes through it) and soft-edged. As plain LOW they were sharp holes rimmed with the Beer–Lambert bright edge, which read as torn paper (zoomed: the first overcast shot, since re-taken).
126. **Cloud light follows the sun after sunset (`uTwilight`).** The brief's cloud colours are daylight's. Unmodulated, clouds at 17:45 (sun near −5°) were 5–13× brighter than the dark sky (measured p50 Y 0.036 against a sky of 0.007; 2.7× at 11:00), pale grey-blue on navy, where v5.1's clouds were tinted from the sky and went dark with it. From 2° above the horizon to 6° under, the daylight fades out of the cloud to the sky's own light (horizon colour × 1.2 on its lit side, mid colour × 0.6 on its shaded side), and golden hour ends with it. The 16:45 evidence (sun at +3.5°) is unchanged.
127. **The backing model's cloud is re-mirrored; `decide()` is untouched.** `skyAt`'s cloud estimate (`backing.ts` `cloudLit`, `cloudLight`, `cloudOver`) now follows the shader: the lit colour with the twilight fade of #126, lit at most by the light's strength × (Lambert + the phase 45° from the light; nearer than that is the sun's or the moon's own neighbourhood), through the LOW sheet's thickness. The first mirror let every cloud be fully lit through the thinnest sheet: at night it estimated Y 0.19 where the sky measures 0.035 (47× the base model's), picked a chip behind 97% of the sweep and ran the sweep into its own timeout. Now the worst of the sweep is 4.72:1 and it takes 20 s (14 s on the base branch; timeout raised to 60 s). It still picks 614k chips against the base's 269k, and those are real: v6's cloud tops are brighter than the deep-blue daytime sky where v5.1's were darker than it, so light text over them needs backing. Two test examples are re-stated for the new sky (a moonlit cloud with the moon up; a cloudless night).
128. **The sun under a deck.** `sunDiscAlpha = exp(−1.8·τ)` as briefed, τ from the CPU field (LOW + MID at the disc), and the deck conditions cap it at 0. The diffuse patch is `0.12·exp(−τ/3)` over a 22% vw radius. With the brief's `exp(−τ)` it is 1.2% of 0.12 under the overcast deck (τ ≈ 2.3) and measured as nothing: rgb(72,80,93) at the sun against rgb(71,78,91) beside it.
129. **A cloud's speed is 0.0014 scene units per km/h**, not the brief's 0.035. At 0.035 a LOW cloud in the upper third of 1440×900 travels about 3,000 px in 10 s against the brief's own 60–120 px. At 0.0014 it travels 65–106 px (unit test, and measured on screen in W2: docs/PROGRESS.md).
130. **Debug hooks.** `?sheet=low|mid|high|scud` isolates one sheet (GPU attribution). `window.__sky` exists in dev as well as test builds (`TEST = SKY_DEBUG`); the evidence script reads the sun's τ from it. Neither is in a production build.
131. **Removed.** The phone's cirrus floor (`uCirrus`: HIGH is a sheet now). `model.ts` `driftVector` / `MIN_DRIFT` and their test: dead since the sheets drift on their planes (#93's screen-space drift is replaced in W2).
132. **A sheet's drift is never wrapped.** The first build wrapped each sheet's offset to "the noise period" (256 units) to keep it small. Only the first octave is periodic there: the rotated octaves (R turns 36.9°), the warp field (half frequency) and the Worley cells (102.4 units) are not, so every wrap would have jumped the whole cloud field: after 40 hours at 15 km/h, one hour at 40 km/h. The offsets are integrated as doubles and sent as they are. A float32 places the fastest sheet (SCUD at 40 km/h) to a texel for a day of continuous play, and LOW, MID and HIGH for days (unit test).

The up-front sky JS is unchanged at 10.7 kB of 13.0, so first paint and Lighthouse are untouched; the cost is 4 kB on a chunk that loads when the browser is idle. **Open for veto:** to hold 26 kB instead, say which to cut. Each later task that outgrows 31 kB raises it again by the smallest amount and logs it here.

The first build had it the brief's way by accident, a sign error in `planeWind`'s depth term that the brief's evidence frames exposed (0 s and 10 s: the clouds rose), and the unit test had encoded the same assumption.
136. **Evolution is a drifting warp field, not a third noise dimension.** A 3D noise is two texture fetches and a mix per sample, which doubles the cloud pass. LOW's two warp fields already move (v3's #93): 0.02/s as briefed. HIGH's cirrus gets one warp of its own (one more fetch): 0.008/s. MID and SCUD only drift. Evolution wraps at 2,560 units, a whole number of noise lattices on every warp input, so it never jumps (36 hours of LOW at a time).
137. **W2's calibration.** 0.0014 scene units per km/h (revises #129's 0.0011, under which the bottom of the upper third moved 51 px): 65–106 px in 10 s by the unit test, 100 px measured on screen in the upper third at 15 km/h. 138. **Rain: slant and depths.** θ = atan((km/h ÷ 3.6) ÷ 7.5), at most 35°, signed by the east–west wind (`src/lib/sky/rain.ts` `rainSlant`): a west wind leans the streaks toward screen-left, which is east. (Revised in #163: the sign only, not a projected size.) The three depths are one pool, and a streak's depth follows the count (50 / 35 / 15), so the near streaks are there at any density. They are drawn per depth and per alpha half: 12 strokes at most, whatever the count.
139. **Splashes are drawn from the clock, on the water.** No state: each mark comes from its birth tick (1/12 s) and its index, a ring 1.5 → 5 px over 0.3 s, at 30 (rain) and 70 (heavy rain and thunder) a second per 1,000 px of width. None in a drizzle, none in a still frame (reduced motion), none on a phone whose mean frame time is over 1/30 s. They are in the landscape layer, above the ground: the particle layer is behind it.

141. **The lights follow the sky, not the clock.** Lamps and windows come on when the mid sky's relative luminance is under 0.04 and go off above 0.048 (`LAMPS_AT`). 144. **What counts as a flash, and the photosafety rule.** The brief's stepped leader, return stroke and up to two re-strokes are four changes of brightness in half a second. Counted are the bright ones (the return stroke, the re-strokes, a sheet flash's pulses): at most three in a strike, all within 400 ms of its beginning, and no two strikes begin within 1.4 s. So any one second holds at most three bright pulses (WCAG 2.3.1). The stepped leader is a thin line at 0.35 and is not counted. `sky-lightning.test.ts` runs 10,000 simulated seconds in each of three storm states: the peak is ≤ 3 in every second, and a natural minute on screen counted 6 bolts and 13 sheet flashes (4–10 and 8–16 asked).
145. **A strike that falls due inside another's second waits for it.** Its due time is computed before the strikes before it have begun. It is tried again every frame until the second has passed, and its next is dated from when it does begin. The first build held it in a slot and dated its next from the stale time: bolts came in pairs 1.4 s apart, 12 in a minute.
146. **A bolt starts below what is written in its column.** Placement rejects `[data-on-sky]` and card rects (`.card`, `.glass`) with a margin of 12% of the bolt's height (how far a channel wanders), six tries, else a sheet flash. On a phone the hero spans the width, so no column is clear: a bolt with 70 px of sky or more below the text starts under it, and without that it is a sheet flash. At the top of 1440×900 about a quarter of the width is clear beside the hero and the cards, so about one natural bolt in five becomes a sheet flash. The debug hook's strike gets sixty tries, so evidence can rely on it.

The bolt's light on the water is a broken column under it in the slow life. That is not the atmosphere's own cost and the brief's remedies cannot reach it (HIGH is not drawn in a storm). ## Flat clouds (replace W1/W2's noise clouds, 2026-11-27)

A browser review of PR #8 found the noise clouds read as smeared paint and marble, covered about 65% of a "partly" sky, banded near the horizon on desktop, blotched on phones, and pushed every header and hero text into a chip. Flat, paper-cut clouds replace them; the rest of v6 stays. Evidence: `.shots/flat-clouds/` (`manifest.json`), the log in docs/PROGRESS.md.

164. **Clouds are flat shapes on their own Canvas 2D layer** (`src/lib/sky/flat-clouds.ts`, `src/components/sky/flat-cloud-layer.ts`), z −3 after the atmosphere, under the particles. Three tones per cloud (BODY, a crisp CAP crescent toward the light, a flat BASE band) and a 1px moonlit RIM at night, drawn source-atop so every edge is the silhouette's own anti-aliased edge: no blur, gradient or texture. Each cloud is a sprite at min(2, DPR), placed on whole device pixels; it is drawn again when its tones or light change, when its puffs have breathed (every 0.5 s, staggered), and never in a still frame. The shader keeps fog, moon glow, horizon glow, rain curtains, the rain darkening, the storm base and the lightning lifts; the sheets, both noise textures, `cloud-field.ts` and `clouds.ts` are gone (`gust` moved to `flat-clouds.ts`).
165. **A deck is 4–6 bands, each a stack of 28–70px strips.** The brief's 4–6 bands at 28–70px cover at most 420px, about half of a 793px desktop sky against 80–92%. So each band (thick overhead, thin toward the horizon, 70 → 28 in proportion) is cut into strips 28–70px thick, 60–140% of the viewport long (on a phone at least five times their thickness, or their round ends eat the coverage), meeting end to end on a shared base, 86–100% of the band's thickness, about a third of their ends leaving a thin gap of sky. Strips never overlap: a thinned strip would show the overlap. A rain deck is closed (no gaps; ends rounded 4px) and hangs its ragged underside from its lowest strip.
166. **Coverage is solved on the rasterised model and aimed inside its band**, 35% in from each edge (partly 21.5–24.5%, 0.6+ cover 45–50%, overcast 84–88%), because the sky on screen drifts a few points either way. Puffs: a size factor, from the mean coverage over three drifts; a deck: its bands' total height (on a 160×90 grid, which counts the thin gaps; a closed rain deck on 64×36). A clear sky keeps one or two small far clouds (0–1.5%). **Short skies miss the deck bands**: the deck starts under the header (#167), so on the 1024×768 scene sky (393px) overcast reaches 77–84% and rain 86–87%; on 375×812 rain is 90–92%.
167. **Decks start under the header's text** (`deckTop` = the lowest header text box + 4px): the header's text is always over open sky. The near layer's band (45–85%) already ends below it.
168. **Text clearing is per cloud, and its factor is solved.** The brief's mask (alpha × 0.30 over the text boxes grown by 28px, 36px feather) was built and rejected after the first review: on puffs it left soft, smeared windows, and on a deck dark boxes around every text. Now a cloud within 28px of a loose text's box is drawn whole but thinner, by that box's factor, easing back over 36px as it drifts away, so its edges stay crisp. The factor is the most of the cloud the text can take without a chip (`backing.ts clearingFor`, to 0.01 on the backing model): 1 where no cloud can reach the box, about 0.1–0.5 behind the hero's light text under white cumulus, 0.3 when even no cloud leaves the text a chip (the clouds are not the cause there). A cloud is never held at 0.30 where it doesn't need to be: a whole rain deck behind the hero needs no thinning.
169. **The backing model reads the flat model**: each puff layer's band and each deck strip row (where a cloud can be, full width, because they drift), the storm's tower (its box), the lightest tone mixed toward the gradient as the layer is, at the clearing factor and the haze alpha. It is the worst case, so a decision doesn't flip as clouds pass.
170. **The header's nav links are `--on-sky`, not `--graphite`.** At 1440 DPR 1 a 14px graphite link over the bare noon zenith (#11284d, no cloud) is 4.91:1 before and 3.96:1 after the model's anti-aliasing (#45 ff.), and no halo makes up that much: every nav link wore a chip on a cloudless desktop sky, before any of this work. CLAUDE.md already defines `--on-sky` as "the hero's and header's secondary text over the open sky"; the links now use it (8.0:1 bare). Hover still goes to `--text`.
171. **"Shipped" at 16:45 is a chip from the dusk sky, not from clouds**: its background with no cloud at all is #856144 at 1440 (the horizon glow) and #665651 at 375, which `--text` at 16px can't reach 7:1 on with any halo. Left, and reported. The same holds wherever else it chips in the matrix (06:20, 17:20 and thunder on a phone, fog at both sizes): no cloud span reaches it there (on a phone it sits below the clouds' horizon; fog has no clouds).
172. **Stars are behind the clouds**: right after the stars the particle layer cuts out the cloud layer's silhouettes (destination-out), and the arc is drawn after that, so it stays on top. **The sun and the moon are occluded by the exact geometry**: a disc inside a near or mid cloud keeps 0.08, linear across its radius, a far cloud counts half, the clearing counted; bodies.ts gets it as τ = −ln(1 − 0.92 · cover) / 1.8. Drizzle joins the deck conditions (no disc, the diffuse patch).
173. **Lightning on flat clouds**: when a strike begins each visible cloud gets a lifted sprite (BODY and CAP +0.25 OKLab L, a thunder cap #8E9AC2), drawn over it at the sheet flash's strength × exp(−(d / r)² · 2.2), plus 0.32 × the bolt's (+8% L on every cloud). The ≤ 3 pulses per second rule is the scheduler's, unchanged.
174. **The cumulonimbus**: static, in a gutter on a desktop (≤ 85% of its width), base on the near band's bottom; on a phone it rises from behind the land at 58% of the width. A solid core under four tiers of puffs and a flat anvil downwind. Its tones are the deck's own, lifted (+0.07 L body, +0.18 L cap): it reads against the dark thunder deck without a new colour.
175. **A deck's tones follow the light**: the weather's tone × (the time of day's body L / the day's body L), its hue half-way to the time of day's away from full day (OKLab), so overcast is mauve-grey at dusk and dark at night, and thunder at 18:30 darker than at noon. Puffs take the time of day's tones (night, civil twilight, golden hour, day at −10°, −4°, 2.5°, 10°), interpolated in OKLab.
176. **Haze thins the layer as one** (the canvas's opacity, 1 − 0.6 · fog), never cloud by cloud: overlapping clouds would show their overlap. Fog itself has no clouds.
177. **Rain curtains**: heavy rain and thunder only (smoothstep 0.8–1 of the rain darkening), alpha ≤ 0.12, a hashed two-octave value noise (no texture). **The storm base** darkens the sky itself (the top of the viewport, 55% → 20% of its height, −30%), since there is no LOW sheet to darken.
178. **Bundle: the idle renderer is 34.8 kB gzip, so neither 26 nor 30 kB fits without dropping v6.** Measured on the production build: up-front 10.6 kB (budget 13), renderer 34.8 kB (34.2 before this work). Gone: the shader's sheets, both textures and their generators, the CPU mirror. Added: the model (4.4 kB minified + gzip on its own, most of it the coverage solver, the deck and the tones) and the layer (2.0 kB). What took the renderer from 26.1 to 34 kB is W3–W6 as much as W1 (#133, #143, #152, #157), and the brief keeps lightning, rain, splashes and fog. Reaching 30 kB means taking about 5 kB of those out or splitting them into a chunk loaded only when the weather needs it; neither was done here. `check-bundle.ts` stays at 35 kB, CLAUDE.md is unchanged. **Open for a decision.**
179. **GPU** (1920×1080 DPR 2, the renderer's timer, medians of six 60-frame samples after the 4 s ease): the atmosphere pass alone (`?clouds=off`, dev and test builds) is 0.74 ms in overcast, from 1.81 before; with the cloud layer on, the timer, which also catches the canvas compositing on the same GPU, reads partly 0.66 ms (1.66 before), overcast 1.49 (1.81), heavy rain 1.60 (1.02): a 93% rain deck is many full-width sprites at 4K. Scrolling partly at 1440×900: 59.8 fps, no task over 50 ms. The first frame (plan + every sprite) is a 50–55 ms task at load, not while scrolling.
